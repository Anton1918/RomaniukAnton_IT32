# Завдання 1. Наївний імпорт

У файлі 10 записів. Проміжну таблицю `drivers_staging` створено без `NOT NULL`/`DEFAULT`/`PRIMARY KEY`, імпорт виконано через `.mode csv` + `.import --skip 1` (роздільник за замовчуванням — кома).

Перші три попередження CLI:

```
v10_raw_rows.csv:2: expected 4 columns but found 1 - filling the rest with NULL
v10_raw_rows.csv:3: expected 4 columns but found 1 - filling the rest with NULL
v10_raw_rows.csv:4: expected 4 columns but found 1 - filling the rest with NULL
```

- `SELECT COUNT(*) FROM drivers_staging;` → **10**
- `SELECT * FROM drivers_staging LIMIT 1;` → у першій колонці `last_name` значення **`Мороз;Анатолій;18;CE`**, решта колонок `NULL`.

Файл збережено з Excel: роздільник — крапка з комою `;`, а CLI очікує кому. Тому весь рядок вважається одним значенням і потрапляє в першу колонку, а решта колонок заповнюється `NULL`. `COUNT(*)` при цьому дорівнює 10, тобто виглядає «правильно», хоча дані зіпсовані. Рядок із `B, C` (запис Олійник) містить кому, тому розпався на два поля («found 2»). Таблицю очищено: `DELETE FROM drivers_staging;`.

# Завдання 2. Правильний імпорт

```
.mode csv
.separator ";"
.import --skip 1 v10_raw_rows.csv drivers_staging
```

Попереджень немає, `COUNT(*)` проміжної таблиці = **10** = кількість записів у файлі; значення стоять у своїх колонках.

# Завдання 3. Контроль якості

**Порожні значення** (`SUM(колонка = '')`): `last_name` 0, `first_name` 0, `experience_years` **2**, `license_category` 0.

**Типи** (`typeof(experience_years)`): `integer` — 8, `text` — 2 (порожній рядок).

Знайдені проблеми:

1. **Порожній стаж** (`experience_years`) у двох записах: **Савчук Ірина** (категорія B) і **Федорук Максим** (категорія C). Порожнє поле імпортується як `''`, а не `NULL`; `typeof` = `text`. Для агрегатів (`COUNT`, `AVG`) такий рядок небезпечний: `COUNT` рахує його як значення, а `AVG` вважає нулем.
2. **Дублікат**: запис **Левченко Роман, 9, CE** зустрічається двічі (`HAVING COUNT(*) > 1`, `cnt = 2`; рядки 6 і 11 файлу, тобто 5-й та 10-й записи).
3. **Роздільник `;`** (див. Завдання 1) — виправлено `.separator ";"`.

Колонки цільової таблиці `drivers` (`.schema drivers`): `last_name`, `first_name`, `experience_years`, `license_category` — усі `NOT NULL`. Тому рядки з порожнім `experience_years` у цільову таблицю не потраплять.

**Розрахунок приросту:** 10 записів − 1 дублікат − 2 записи з порожнім стажем = **7 рядків** до додавання.

# Завдання 4. Перенесення з виправленням

До перенесення: `COUNT(*) = 13`, `MAX(id) = 13`.

Спроба перенести з `NULLIF(experience_years, '')` завершилася помилкою `NOT NULL constraint failed: drivers.experience_years` — `INSERT ... SELECT` не додав жодного рядка. Значення не вигадувались, тому перенесено лише повні рядки:

```sql
INSERT INTO drivers (last_name, first_name, experience_years, license_category)
SELECT DISTINCT last_name, first_name, experience_years, license_category
FROM drivers_staging
WHERE experience_years <> '';
```

**Відкладено (потребують уточнення власником даних):** Савчук Ірина (B) і Федорук Максим (C) — не вказано стаж, а в `drivers` він обов'язковий.

Після перенесення: `COUNT(*) = 20`, `MAX(id) = 20`. Приріст **7** збігається з розрахунком із Завдання 3. Нові `id` — від 14 до 20, нумерація продовжила попередню. `SELECT COUNT(*) FROM drivers WHERE experience_years IS NULL;` → **0**: у цільовій таблиці `NULL`-значень немає, тому що рядки з порожнім полем було відкладено. Проміжну таблицю видалено (`DROP TABLE drivers_staging;`).

# Завдання 5. Експорт у CSV

```
.headers on
.mode csv
.output drivers_export.csv
SELECT id, last_name, first_name, experience_years, license_category FROM drivers WHERE id > 13;
.output stdout
```

Вміст `drivers_export.csv`:

```
id,last_name,first_name,experience_years,license_category
14,"Мороз","Анатолій",18,"CE"
15,"Тимошенко","Ганна",7,"D"
16,"Олійник","Степан",11,"B, C"
17,"Левченко","Роман",9,"CE"
18,"Головко","Сергій",2,"B"
19,"Кушнір","Богдан",14,"C"
20,"Ярошенко","Лідія",5,"D"
```

- **Роздільник** — кома (`.mode csv` повертає роздільник-кому; після `.separator ";"` потрібно знову виконати `.mode csv`).
- **Кома всередині значення** (`B, C`) записана в подвійних лапках, тому не розриває поле.
- **Текстові значення** беруться в лапки, числа — без лапок.
- **`NULL`** записується як порожнє поле (`,,`). У цьому експорті `NULL` немає, бо всі рядки мають стаж.

Якби такий файл імпортували назад, порожнє поле повернулося б порожнім рядком `''`, а не `NULL` (тип — `text`). `NULLIF(колонка, '')` знову перетворив би його на `NULL`.

# Контрольні запитання

1. Режим `.mode csv` з комою «проходить» формально: CLI лише друкує попередження й вставляє рядок як є. Весь рядок з `;` опиняється в першій колонці, решта — `NULL`, а `COUNT(*)` виглядає правильним. Помітити це можна за попередженнями `expected 4 columns but found 1`, за `SELECT * ... LIMIT 1` (повний рядок у першій колонці) і за колонками з самими `NULL`.
2. Порожнє поле імпортується як `''`, а не `NULL`. `COUNT(колонка)` рахує його як значення, `AVG` вважає його нулем, а `typeof` показує `text` у числовій колонці. Тому перед перенесенням порожні рядки перетворюють на `NULL` через `NULLIF` (або відкладають, якщо колонка `NOT NULL`).
3. У проміжній таблиці дані ще можна безпечно перевіряти й чистити (`SELECT`, `GROUP BY`, `DELETE`), не торкаючись справжніх даних. У цільовій таблиці дублікати вже мають власні `id`, їх складніше відрізнити від потрібних записів, а помилки доведеться виправляти в робочих даних.
