# Завдання 1
`UPDATE trips SET duration_min=160 WHERE id=1;`
Тривалість: **150 → 160 хв**. UPDATE використано, бо запис уже існував.

# Завдання 2
`UPDATE routes SET distance_km=155.0 WHERE id=1;`
Відстань: **150.0 → 155.0 км**. UPDATE доречний для зміни існуючого показника.

# Завдання 3
`DELETE FROM trips WHERE id=10;`
Кількість поїздок: **10 → 9**, тобто видалено рівно один рядок.

# Завдання 4
Для `trips.driver_id → drivers.id` та `trips.route_id → routes.id` використано `ON DELETE RESTRICT`.
Спроба видалити водія `id=1`, на якого є посилання, дає: **FOREIGN KEY constraint failed**.
Отже, історичні поїздки не дозволяють видалити пов'язаного водія.

# Контрольні питання

1. `UPDATE ... SET колонка = колонка + 1` змінює значення відносно поточного, а `SET колонка = число` встановлює конкретне однакове значення для вибраних рядків.
2. `NOT NULL`, `UNIQUE` і `CHECK` перевіряються і при UPDATE, бо оновлення теж може порушити цілісність даних.
3. `ON DELETE CASCADE` автоматично видаляє залежні записи, а `RESTRICT` забороняє видалення батьківського запису, якщо є залежні.
4. `DELETE` без `WHERE` небезпечний, бо видаляє всі рядки таблиці.
