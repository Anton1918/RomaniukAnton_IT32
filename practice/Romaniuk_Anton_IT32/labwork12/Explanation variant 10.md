# Завдання 1 
**ORDER BY:** таблицю `trips` відсортовано за датою рейсу від найновішої до найстарішої.

# Завдання 2 
**Кілька колонок:** рейси впорядковано за тривалістю за спаданням, а дату використано як другий критерій.

# Завдання 3 
**Top-N:** через `ORDER BY duration_min DESC LIMIT 3` отримано три найдовші рейси. Сортування має стояти перед `LIMIT`, інакше SQLite вибере три рядки без гарантії, що вони найдовші.

# Завдання 4 
**DISTINCT / BETWEEN / IN:** отримано унікальні категорії посвідчень; `BETWEEN 130 AND 140` вибирає маршрути в заданому включному діапазоні; `IN` зручно перевіряє належність до переліку пунктів відправлення.

# Завдання 5 
**LIKE та кирилиця:** шаблон `LIKE 'Шев%'` знаходить прізвище Шевченко. У SQLite стандартний `LIKE` нечутливий до регістру для ASCII, але не для кирилиці, тому `LIKE 'шев%'` може повернути інший результат (у цій базі — жодного рядка).

# Контрольні питання

1. `ORDER BY` спочатку впорядковує рядки, а `LIMIT 3` залишає перші три вже відсортовані рядки. Якщо прибрати `ORDER BY`, SQLite поверне будь-які три рядки без гарантії, що це найдовші рейси.
2. `IN` перевіряє належність до конкретного переліку значень, а `BETWEEN` — чи потрапляє значення в діапазон, включно з обома межами.
3. У SQLite стандартний `LIKE` зазвичай не розрізняє регістр для ASCII, але розрізняє для кирилиці. Тому шаблони `LIKE 'Шев%'` і `LIKE 'шев%'` можуть повертати різні результати.
