# Завдання 1. HAVING на COUNT
Запит групує поїздки за водієм і залишає групи, де більше однієї поїздки. Результат: `[(1, 3), (2, 2), (3, 2), (5, 2)]`.

# Завдання 2. HAVING на AVG
Запит показує водіїв, середня тривалість поїздок яких менша за 200 хв. Результат: `[(1, 171.66666666666666), (2, 187.5), (3, 142.5), (4, 80.0)]`.

# Завдання 3. WHERE + GROUP BY + HAVING
`WHERE duration_min >= 100` фільтрує окремі поїздки перед групуванням, `GROUP BY` формує групи за водієм, а `HAVING COUNT(*) >= 2` залишає групи з двома або більше поїздками. Результат: `[(1, 3, 171.66666666666666), (3, 2, 142.5), (5, 2, 217.5)]`.

# Завдання 4. Навмисна помилка
SQLite повідомляє про неправильне використання агрегатної функції (`misuse of aggregate: COUNT()`), оскільки `WHERE` працює до групування. Умови з `COUNT`, `AVG` та іншими агрегатами слід задавати через `HAVING`.

# Завдання 5. LEFT JOIN + GROUP BY + HAVING
`LEFT JOIN` зберігає всіх водіїв, навіть якщо в них немає поїздок. `HAVING COUNT(t.id) < 3` залишає водіїв із менш ніж трьома поїздками. Результат: `[(2, 'Коваленко Максим', 2), (3, 'Бондаренко Андрій', 2), (4, 'Мельник Дмитро', 1), (5, 'Ткаченко Віталій', 2)]`.

# Контрольні питання

1. `COUNT(*) > 1` у `WHERE` не працює, бо `WHERE` фільтрує рядки до групування; агрегатні умови належать до `HAVING`.
2. Якщо замінити `LEFT JOIN` на `INNER JOIN`, водії без поїздок зникнуть із результату.
3. `WHERE` відбирає рядки, `HAVING` — готові групи. Логічний порядок: `FROM/JOIN → WHERE → GROUP BY → HAVING → SELECT → ORDER BY`.
